# 任務拆解（To-Tickets）：示蹤彈任務與依賴圖建立

本技能將架構規格書或討論共識，拆解為端到端可驗證的垂直切片（Tracer-bullet）任務票券，並清楚宣告各任務間的「阻擋相依（Blocked by）」關係。

## 核心鐵律與確認閘門

> [!IMPORTANT] 確認閘門（Approval Gate）
> - **先預覽後寫檔**：票券清單與相依性拓撲圖必須先在對話中呈現供 CK 審閱。未經 CK 明確核准，不得在磁碟建立票券檔或在遠端建立 Issue。
> - **單一垂直切片原則**：每個切片須完整貫穿各層（Schema、API、邏輯、測試），可獨立驗證；嚴禁按技術層水平切割。
> - **廣域重構採擴充-收縮（Expand-Contract）**：涉及全域符號或架構調整時，先擴充新介面並行、再批次遷移、最後收縮移除舊介面。

## 執行流程

1. **研讀規格與脈絡**：讀取規格書或對話內容，確認所有驗收條件。
2. **規劃垂直切片與拓撲圖**：
   - 梳理前置重構（Prefactoring）與主要切片。
   - 標明每個切片阻擋哪項任務、受哪項任務阻擋（Blocked by）。
3. **向 CK 提出預覽審閱**：
   - 粒度是否恰當（不宜過粗或過細，每個切片適合在一個獨立脈絡窗口內完成）。
   - 相依阻擋是否合乎邏輯。
4. **取得確認後寫檔**：
   - 經 CK 同意後，寫入 `.agent/tickets/<NN>-<slug>.md`，依序編號。

## 票券標準格式（.agent/tickets/NN-slug.md）

```markdown
# <NN>: <任務標題>

**交付價值：** 從使用者與端到端行為角度描述本任務達成的具體驗證行為。
**阻擋條件（Blocked by）：** <相依的任務編號或無（可立即開始）>
**狀態：** 待執行（ready-for-agent）

## 驗收清單
- [ ] 驗收項目 1（測試 seams 驗證通過）
- [ ] 驗收項目 2（符合安全編碼規範）

## 限制與備註
- 不寫入特定可能快速失效的行號；專注於合約與資料流。
```
